# Integrations

Coglatas has a tenant-scoped integration foundation for future Google, Microsoft, Slack, Discord, GitHub, Autodesk, and custom webhook work.

## Current MVP

Implemented:

- `IntegrationAccount`
- `WebhookEndpoint`
- `ApiToken`
- Tenant admin APIs for integrations, webhooks, and API tokens.
- API token validator service skeleton.
- Raw API token is returned only once at creation.
- Token hashes are stored instead of raw tokens.
- Webhook secrets are stored as hashes when supplied.
- Webhook test endpoint validates configuration only; it does not send outbound requests.

Not implemented yet:

- OAuth provider flows.
- Secret-provider integration for OAuth refresh tokens or webhook signing secrets.
- Outbound webhook delivery.
- API token authentication middleware.
- Provider-specific sync jobs.

## API Surface

Integrations:

- `GET /api/tenant/integrations`
- `POST /api/tenant/integrations`
- `GET /api/tenant/integrations/{integrationId}`
- `PATCH /api/tenant/integrations/{integrationId}`
- `DELETE /api/tenant/integrations/{integrationId}`

Webhooks:

- `GET /api/tenant/webhooks`
- `POST /api/tenant/webhooks`
- `GET /api/tenant/webhooks/{webhookId}`
- `PATCH /api/tenant/webhooks/{webhookId}`
- `DELETE /api/tenant/webhooks/{webhookId}`
- `POST /api/tenant/webhooks/{webhookId}/test`

API tokens:

- `GET /api/tenant/api-tokens`
- `POST /api/tenant/api-tokens`
- `POST /api/tenant/api-tokens/{tokenId}/revoke`

## Security Rules

All integration data is tenant-scoped and implements tenant filtering through `ITenantEntity`.

Tenant admins can manage integrations in the current tenant. Platform admins can manage tenant integration data only through explicitly authorized tenant-scoped requests.

`SettingsJson` on `IntegrationAccount` must not contain raw secrets, tokens, passwords, API keys, private keys, or OAuth refresh tokens. Store only non-sensitive config in the MVP.

`WebhookEndpoint.SecretHash` stores a hash only. Raw webhook secrets must not be logged or returned.

`ApiToken.TokenHash` stores only the token hash. Raw token values are generated by the application and returned only once in the create response.

Revoked or expired API tokens must fail validation. API token usage must never bypass tenant filtering; the validator returns the token tenant so future middleware can set tenant context before protected operations.

## Feature Flags

- `WebhookIntegration` blocks webhook APIs when disabled.
- `ApiAccess` blocks API token APIs when disabled.

## OAuth Later

OAuth provider work should add:

- Provider-specific authorization initiation and callback endpoints.
- Per-tenant provider configuration.
- Secret storage through a secret provider or vault.
- Refresh token rotation.
- Audit logs for connect, refresh failure, disconnect, and permission changes.

## Webhooks Later

Outbound webhook delivery should add:

- Event selection and payload contracts.
- Background delivery queue.
- Retry policy with backoff.
- Signature generation from a secret provider.
- Delivery logs with redacted headers and payload summaries.

## On-Prem Considerations

On-prem installations may need internal HTTP endpoints for integrations. The MVP rejects HTTP webhook URLs by default. Any future override must be explicit in configuration, clearly documented, and disabled for SaaS production.
