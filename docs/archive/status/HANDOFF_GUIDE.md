# Handoff Guide

This guide is for a developer, teacher-technologist, or operator taking over a controlled pilot or school demonstration.

## Repository Structure

```text
src/
  Coglatas.Web/             ASP.NET Core startup, middleware, controllers, static UI
  Coglatas.Application/     Use cases, DTOs, authorization services, service contracts
  Coglatas.Domain/          Entities, enums, common domain interfaces
  Coglatas.Infrastructure/  EF Core, migrations, repositories, files, audit, search
tests/
  Coglatas.Tests/           Unit and service-level tests
docs/
  *.md                       Architecture, operations, release, and pilot docs
```

## Main Modules

- Auth and Admin: login, invite registration, user administration, system settings.
- Tenancy and TenantAdministration: tenants, memberships, settings, features, quotas, plans, subscriptions, usage.
- Workspaces, Groups, Channels: collaboration structure, posts, threads, pinned posts.
- Messaging: direct/group conversations, messages, members, unread state.
- Announcements and Notifications: broadcast messages, read confirmation, notification read state.
- Projects and Planning: projects, milestones, tasks, assignments, dependencies, comments, Gantt, dashboards.
- Files and Artifacts: upload policy, file metadata, authorized download, artifact versions.
- Forms and Events: scoped forms/surveys/applications plus event/attendance/calendar basics.
- Search and Audit: tenant-filtered search, audit logs, security events.
- UiShell: feature modules, panels, layouts, commands, and radial menu registry data.

## Authentication

The current app uses cookie authentication for browser and same-site API flows. Login is `POST /api/auth/login`; current user is `GET /api/auth/me`; logout is `POST /api/auth/logout`. Invite registration is `POST /api/auth/register-by-invite`.

Password reset is not implemented. API token creation and validation exist as a foundation, but request authentication middleware for API tokens is not implemented.

## Tenancy

Tenant is the top isolation boundary. Tenant-owned entities implement `ITenantEntity` and are filtered by `AppDbContext` global query filters. `AppDbContext` also stamps new tenant-owned records and rejects mismatched tenant IDs.

Normal tenant-scoped endpoints must use the current server-resolved tenant. Do not accept `TenantId` from request bodies. Platform scope is reserved for explicit `/api/platform/*` operations.

## Authorization

Controllers should remain thin. Authorization belongs in application services and module authorization services. Use controller attributes only as an outer guard; every resource operation still needs application-layer checks.

Role split:

- `PlatformAdmin`: system-level tenant/platform operations.
- Tenant `Owner`/`Admin`: current-tenant administration only.
- Workspace/group/channel/project roles: resource-specific permissions.

## File Storage

File bodies go through `IFileStorageService`. Metadata is stored in `FileObject`; storage keys are generated by the application and include the tenant namespace. Local filesystem storage is implemented. Object storage provider names exist in configuration but production adapters are not implemented.

Downloads must pass application authorization before returning bytes. Do not expose raw permanent storage URLs.

## Production Tracking

Projects belong to a workspace and optionally a group. Project members authorize access to milestones, tasks, assignments, dependencies, comments, artifacts, Gantt data, dashboard data, and workload/my-task queries.

Keep production-tracking business rules in `Coglatas.Application.Projects` or `Coglatas.Application.Planning`, not in controllers.

## UI Registry

The UI shell is backed by `FeatureModule`, `PanelDefinition`, `UserLayout`, `CommandDefinition`, `RadialMenuProfile`, and `RadialMenuItem`. It is a foundation for feature-aware navigation, docking, commands, and future radial menu work. It is not a complete free-form desktop.

## Where To Add New Features

Add a feature slice by following existing modules:

1. Domain entities/enums in `Coglatas.Domain`.
2. DTOs, service interface, service, and authorization service in `Coglatas.Application`.
3. Repository contract under `Coglatas.Application.Common.Interfaces` when needed.
4. EF repository/configuration/migration in `Coglatas.Infrastructure`.
5. Thin controller in `Coglatas.Web.Controllers`.
6. Tests under `tests/Coglatas.Tests/<Module>`.
7. Docs for operational or security behavior.

## Where Not To Put Business Logic

- Do not put resource authorization in controllers only.
- Do not put tenant isolation decisions in frontend code.
- Do not query EF entities directly from controllers for user-facing APIs.
- Do not create tenant-owned records from request-body tenant IDs.
- Do not use `IgnoreQueryFilters` in normal application services.
- Do not use file names as storage paths.

## Common Dangerous Mistakes

- Enabling development tenant headers in production.
- Leaving `Platform:PlatformAdminSetupMode=true`.
- Marking features complete before manual smoke or automated tests exist.
- Treating local filesystem storage as production SaaS storage.
- Assuming tenant metadata export is a full restore.
- Exposing token hashes, password hashes, webhook secrets, or storage keys as usable download URLs.
- Adding a new tenant-owned table without `ITenantEntity`, indexes, and tenant tests.
