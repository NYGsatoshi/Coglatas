## Verification Rules

- Angular screens must consume frontend view models. Live API wiring must add adapter/facade mapping layers that translate backend DTOs into the existing view models under `frontend/src/app/features/**`.
- Components must not consume raw backend DTOs directly and must not infer missing DTO fields from mock data.
- Backend authorization is the source of truth. UI hiding is a usability hint only, not authorization.
- Backend route, DTO, enum, error, and authorization gaps below must become backend issues or explicit adapter constraints, not guessed frontend behavior.
- JSON property names are camelCase by default because `AddControllers()` uses ASP.NET Core defaults and there is no global JSON enum converter. DTO field lists below use browser JSON names.
- Enum serialization is numeric for most JSON body/response enums. `ConversationType` is the exception because the enum type has `[JsonConverter(typeof(JsonStringEnumConverter))]` and must use exact backend names such as `DirectMessage` and `ProjectChannel`.
- Unsafe browser requests require `X-CSRF-Token` from `GET /api/security/csrf-token` when CSRF protection is enabled.

## Backend Issues / Gaps To Track Before FE-23

1. Standardize API error envelope and status mapping. Current controllers mix `ErrorResponse(code,message,traceId)` and legacy `{ error }`, and many authorization/not-found failures return `400`.
2. Decide enum serialization policy. Most enums are numeric in JSON, while `ConversationType` is string. Smoke examples already contain string enum values that are invalid for several DTOs, including `ConversationType` value `"Direct"`.
3. WS-02 is the merged active-Workspace boundary. The WS-03 candidate must keep Workspace create capability-gated, reuse one `Idempotency-Key` for an unchanged uncertain retry, and activate a verified 201 only after the new ID appears in a refreshed authorized list. A committed-but-not-activated resource must use GET/selection-only recovery. Exact-final-head verification remains required for WS-03.
4. Add paged workspace member query fields for live grid needs, or explicitly limit FE-23 to loaded-row local search only.
5. Keep Announcement publishing bounded to the verified audience adapter and immediate confirmation candidate. Add a server idempotency/replay contract before exposing retry semantics, and define an approved persisted scheduling/timezone/scheduler contract before exposing scheduling, saved drafts, or a scheduled-publication claim.
6. Add messaging idempotency (`clientRequestId`) and canonical attachment ID support. Do not wire retry sends against the current DTO as if idempotency exists.
7. Preserve message body privacy and participant-bound moderation. UI controls must not compensate for backend authorization gaps.
8. Add file list, scan status, quota, uploaded-by display, and download policy DTOs. Verify upload cleanup for storage-saved/metadata-failed cases.
9. Keep file download gate backend-owned. Direct download currently issues and uses a short-lived grant, with scan/status/authorization rechecks.
10. Add project/task view fields for frontend status labels, allowed transitions, comment author display, and concurrency/row-version behavior.
11. Add notification target route contract for Angular routes or typed target mapping. Current `targetRoute` values are backend-style paths.
12. Preserve the backend-owned `AuditGridRowResponse` boundary and Issue #344 filter contract. Frontend must not parse `metadataJson`; local saved views store input only. Raw metadata outside the exact-event disclosure, duration, Claim/Evidence, server-shared views, immutable snapshots, and realtime results require separate contracts.
13. Add export diagnostics list/projection and clarify whether export jobs are immediate file downloads or asynchronous jobs for the admin grid.
14. Fix invite acceptance transaction or document intended behavior: current registration creates user/session and marks invite accepted but does not verify tenant/workspace membership creation.
15. Add account sessions/profile endpoints if the account page should show live sessions, revoke controls, tenant summary, and workspace summary.
16. Keep global search hidden until route-target mapping and authorization parity are explicitly verified. `SearchController` exists, but there is no Angular search route in the P0 menu.

## FE-23 API Wiring Boundary

Recommended next issue: **FE-23 API wiring pass**.

Scope for FE-23 should be adapter-first:

- Add per-feature API adapters that map backend DTO JSON to existing frontend view models.
- Keep the current mock facades as the fallback/test source until each screen moves from `Partial`/`Blocked` to `Ready`.
- Wire only endpoints whose DTO fields and enum formats are verified in this document.
- Preserve password strings exactly; do not trim password fields.
- Use `userId` consistently for current-user identity.
- Use CSRF service for unsafe first-party API calls.
- Do not add UI-only authorization decisions. Backend denial must remain authoritative.
