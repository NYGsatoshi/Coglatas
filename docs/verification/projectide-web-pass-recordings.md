# Original pass recordings in the offline Angular Workbench

This bounded #1034 / #782 Product slice consumes the separately owned local
initial-root pass recordings in Angular. The Windows pure ViewModel and actual
Preview producer are documented in projectide-pure-workbench-pass-recordings.md.
There is no new browser Compiler, backend transport, actual Avalonia or current
runtime authorization/retention service.

## Actual original fixture and strict local recipe

The new pass-recordings-v1.json asset is the unmodified Windows original exported
by the actual --pass-recordings Product binary after #2005 qualification. Eleven
existing Boolean/Requirement inputs each have six actual local attempts: original
Manifest, diagnostic original JSON, capture-byte limit, event limit, pre-cancelled
attempt and a distinct retry linked to that cancelled origin. The existing
Source/input/result/root/premise subjects stay unchanged. Original random run,
attempt, manifest, response and receipt identities are retained rather than
restamped to resemble the browser read or a current global run.

The reader verifies all six members and all snapshot choices before admitting
one selected run. Original Source/input/request/policy/base/materialization/
manifest/response/receipt/result/record/snapshot/body text uses exact UTF-8 hashes,
not parse-and-reserialize hashes. Duplicate members (including escaped duplicate
names), malformed Unicode, unsupported structures and fractional/exponent aliases
in integer protocol metadata are refused. Source/result/original body JSON keeps
its own original numeric tokens. Admission bounds include16MiB of aggregate
string content,4MiB per frame,100000 inspected structural nodes and depth64.
The actual exporter separately bounds the complete serialized projection at16MiB.

This separate v1 offline recipe deliberately covers the eleven completed
initial-root inputs, empty host materializations, declared1MiB/one-byte body
capture and16/one event limits. It is not a general artifact deserializer or
formal Registry/Reader schema adoption. Other recipes are refused. The exact
request, policy, input, compiler, context, generation, response, receipt, actual
origin chain and all-case session/run/attempt uniqueness must agree. Local
hashes and producer platform/runtime/assembly metadata establish no trusted
producer or authenticity of an arbitrary external file.

## Boundaries, original bodies and independent axes

The actual ten entry/return boundaries preserve their order: parse/normalize,
binding, semantic validation/IR, analysis and root publication. Typed body roles,
domains, byte counts and original digests are checked. Source/input references
bind both the admitted original digest and its known UTF-8 text length in every
capture mode, including Manifest and capture-byte gaps without retained bodies.
Semantic/IR/map references bind the original result
artifacts. The case with no produced IR retains its original explicit gap and
no invented semantic outputs. Root publication precedes dependency attachment;
its body is not treated as an alias for every possible final result.

Manifest keeps observed boundary metadata but stores no bodies. Original body
capture and event-limit gaps remain separate from a later viewing byte limit.
Available snapshots must contain exactly the original distinct referenced bodies,
with their exact original text/hash/length and atomic byte accounting. A larger
view cannot fill an old capture gap; a small view does not rewrite the original
capture. No binding engine object, lazy supply, regional evaluation, optimizer,
plan, FullDump, FullTrace or causal explanation is invented.

The cancelled host member has no result, record or snapshots. The currently
shown case result is not borrowed as its result. Host completion, Compiler
execution/coverage/verdict/evidenceComplete, original capture and viewer budget
stay separate. Requirement condition examples retain evidenceComplete=false.
Reading pass bytes does not satisfy the Requirement or turn a result into PASS.

## Explicit UI and current ownership

Open the recorded pass example, choose an input, load its result and explicitly
read the fixed root Source. Source then offers each existing run and its actual
run/attempt/origin and capture counters. Boundary order is visible from metadata;
original bodies require another explicit read. Manifest is the default.
Available original JSON and a one-byte viewing limit are separate actions.
Whole-pass views need no selected diagnostic; existing selected operator and
predicate panels retain their own diagnostic bindings.

English/Japanese labels, keyboard activation, loading/unavailable feedback and
verified focus follow the Workbench pattern. Original metadata and bodies remain
separately expandable. Capture/event/viewer limits and cancellation do not erase
or reinterpret the case result. The layout wraps long original digests at narrow
widths.

Private WeakMaps bind admission to the current case, root admission, exact
projection/member references and a private full fingerprint. The store captures
the intended manifest text/digest and object identity before awaiting verification.
Source/run/input replacement, missing bundle membership, global identity reuse,
newer asynchronous reads, denied state and protected-state clearing withdraw the
applicable metadata/body views. Focus callbacks recheck generation, permission
visibility and the current admitted reference. Selection changes alone do not
invalidate a whole-root pass snapshot. Withdrawal is not physical deletion of
returned caller-owned immutable text or current server-side authorization.
