# Message search mobile opening focus

Issue [#1356](https://github.com/NYGsatoshi/Coglatas/issues/1356) records a first-attempt Chromium-mobile failure at Main `f6feb88754473455e04553c911fc6380895f2e52`: the advanced-filter drawer was absent after keyboard activation; retry 1 passed. The successful job skipped its failure-only browser upload, so the first-failure trace is unavailable. Its historical cause remains unknown. This candidate does not close or waive that failure.

The demonstrated independent path is narrower: a deferred mobile-panel opening callback can move focus back to search after a user deliberately focuses the advanced-filter trigger. The candidate retains the opening focus when its originating focus intent is still current, checks that the mobile panel remains open and the advanced drawer remains closed, and cancels and invalidates pending mobile focus on toggle-close, Escape, advanced transitions and component destruction. A generation guard also rejects a callback that was already queued when cancelled. Existing advanced-drawer, search and filter behavior is preserved.

The real-component controls retain ordinary keyboard and pointer opening, deliberate advanced-trigger selection before the callback, and late callbacks after toggle-close, Escape, advanced opening or destruction. The controlled browser diagnostic holds only the actual mobile focus callback and uses native Enter with the original build and corrected build; it is distinct from an unmodified reproduction of the hosted timing. Original browser test assertions, retries, timeouts and screenshot baselines are unchanged.

Exact source/build identities, all diagnostic failures, focused unit/browser results, traces and owned container cleanup are retained in the coordinator's local evidence. A configured control is not proof it ran. Local static/mock and component controls do not establish backend, licensed acceptance, HTTPS staging, RLS, backup/restore/rollback, or release qualification. Both Owner HOLDs and NO_GO remain.
