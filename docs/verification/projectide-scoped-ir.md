Existing Product ownership: #905 / #888 / IDE-START-01, paired with #1032. It is a development artifact, not ordinary external project-ir/1 publication, a runnable plan, formal Artifact Registry adoption or current foreign-read authority.

## Exact context slots

The normal dependency pipeline produces ScopedIr only when its binding closure is complete, its declared graph is structurally validated, every exact binding region is present once, and every regional semantic validator produced IR. False/Unknown required rules remain separate from structural lowering: a known false Constraint can have structural IR while the actual Compiler verdict remains FAIL. Missing eligible evidence or Resource evaluation cannot become a Compiler PASS.

The root input, binding-closure digest, global-graph digest, original Source context/digest, exact binding-region digest and each actual regional IR digest bind the artifact. The separate source map binds the same root and exact contexts with each regional map and digest. Dependency analysis includes the aggregate digest, so the normal root result's dependency-stage evidence changes when aggregate production changes.

Stable IRNodeId retains its existing Tenant/Project/Entity/role derivation. Multiple versions of one Project occupy separate context slots; they are never flattened into one node dictionary or assigned invented identities. Every relation endpoint is checked against an exact admitted context/entity and, when present, PortId. Relation lookup is owner-context-qualified. ResolveNode and ResolveRelation return original captured-source locations only. A different/unadmitted revision does not fall back to latest or a matching EntityId. Runtime/reader adapters must separately verify original bytes, compatibility, freshness and current read/navigation authority.

Development formats are coglatas.project-ir-closure/1 and coglatas.semantic-closure-source-map/1. Embedded regional manifests remain root-bound binding receipts; they are not independent compiler/cache inputs or reconstructed dependency Scenario intent. Existing purely local IR and identity contracts are unchanged. Version-one normal external Validation.Ir remains absent and retains the external-closure-not-lowered guard. The later explicit version-two scoped-publication follow-up produces normal model/IR/map artifacts and both original-byte consumers; it does not remove the version-one guard or grant runtime/security acceptance.
