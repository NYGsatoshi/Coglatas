# Bounded pure elapsed simulation engine

Authority: #907 accepted discrete-event virtual clock and immutable rerun boundaries, #905 actual plan definitions and #888 A-R2. This is an initial pure library slice over the actually produced `CompilerExecutionPlan`, not full #907 acceptance or a runtime job endpoint.

`SimulationRunManifest` owns the actual immutable plan reference and binds its digest, compiler input and Source, explicit caller-provided run identity, explicit nonnegative virtual start, versioned engine, stable scheduling policy, stochastic None, side effects None and all event/operation/elapsed-time/trace-byte bounds. An optional prior-run digest is an origin link, not a proof of ancestry or current authority. No ambient UUID, machine clock, calendar, seed, network, provider, file or secret enters execution. Replaying an identical manifest produces identical result bytes; a rerun with another identity/input/settings has a distinct manifest/result. Run identity alone is not a global registry: consumers must retain the full manifest/digest binding.

The initial owned engine is `coglatas.elapsed-fs-simulator/1`. It only consumes the existing lowerer's complete known nonnegative elapsed Task DAG. Unsupported/Unknown declarations and missing required validation cannot manufacture such a plan; the simulator does not parse arbitrary caller-supplied plan JSON. Every exact captured context remains a distinct execution slot even when stable Task IR node IDs match. The definition and original Source are never modified.

Each ready Task starts at the virtual start, independent of other ready Tasks. Ending a prerequisite updates every dependent's ready time to the maximum of all prerequisite ends plus the corresponding lags. A dependent is enqueued only after every prerequisite has ended. Capacity is explicitly unlimited; this is not resource allocation or an optimization solver. The priority is virtual time, end before start, ordinal canonical context and IR node identity, then enqueue sequence. Zero-duration events remain finite and causally enqueued; an end created by its start cannot precede that start. The plan's definition order is never used as a serial runtime call stack.

Events retain exact original context, node and typed location, processed sequence, enqueue sequence, kind and canonical elapsed tick string. Tick addition is checked; overflow preserves the recorded prefix and returns explicit InternalError rather than wrapping time. Arithmetic checks do not alter #1128's numerical assurance status.

Provisional run bounds are separate from existing compiler profiles and CI policies. Preparation charges the bounded plan representation before allocating indexes. Task/edge/queue/transition and serialized-event work consume the declared logical budget. Each transition is fully checked before state/trace publication. Event, inclusive elapsed-time, logical-operation or trace-byte exhaustion preserves only the committed prefix with ResourceExhausted and partial/none coverage. Cancellation is polled during preparation and event work; it preserves a prefix with Cancelled. There is no wall-clock timeout implementation or performance/capacity guarantee. Trace capture stops execution at its bound; it does not pretend an unrecorded event happened or reconstruct missing values.

`ProjectSimulationRun` owns a read-only event collection and original canonical data/digest. Execution, computation/trace coverage and input freshness are separate. Stale expected input or unsupported engine is NotRun with no events. A zero-Task definition is explicitly NotRun. No outcome assertions are evaluated: verdict remains NotRun with `coglatas.no-outcome-assertions`, even when simulation execution completes. Evidence is explicitly `coglatas.simulation`, not a Compiler/Test PASS, real-world observation or current eligibility.

## Verification scope and next slice

Executable pure tests cover parallel roots and unequal join lags, simultaneous/zero-duration ordering, source-set reordering, exact manifest replay and new-run origin links, public collection/byte mutation, event/time/operation/exact trace-byte bounds, stale input, unsupported engine, pre-cancellation, checked overflow and repeated captured Task versions. Original failing verification is retained in the continuation evidence; the initial collection test incorrectly assumed a read-only `IList` implementation could not exist, and now exercises actual rejected mutations.

Both client adapters and visible run controls remain at their previously implemented plan-definition depth. This slice does not yet expose a Web or Windows simulation UI, original-byte run transport, debugger break/step/watch, waiting-state inspection, Scenario/new-run comparison, Resource/Workflow execution, server jobs or persistence. Those are the next paired consumer slices and remain open under #907. Pure Core execution is not actual Avalonia/native acceptance.
