# Paired original operator Inspector

This bounded #1034 Product slice connects the owned local initial-root operator
host to the Angular synthetic Workbench and the Windows pure ViewModel. It
preserves the earlier ordinary host, output recording and Proof-array recording
protocols. It reads actual supplied frames; it does not reconstruct an operator
tree from diagnostic references or turn a later run into an earlier capture.

## Declare the Windows invocation before execution

SyntheticWorkbenchViewModel.BeginOperatorSynthetic receives the exact immutable
PredicateObservationCompilerHostRequest and owned predeclared Manifest before
publishing Waiting. The returned context is required by
TryAcceptOperator together with the actual response/receipt pair. Root Source,
input, context, compiler, materializations, policy, client generation and intended
result are checked against that owned invocation. An older genuine pair cannot
be attached to a new declaration. Normal/array contexts cannot accept operator
responses, and operator contexts cannot borrow ordinary admission.

ReadOperatorRecordingMetadata is explicit and exposes the verified run/attempt,
origin, capture metadata and original Manifest/receipt. ReadRecordedOperators
requires the actual selected diagnostic and the same explicit root Source;
Manifest is the default. AvailableOperators returns only supplied original node
and ordered evaluation frames named by that selected diagnostic. Execution
counts, original capture sufficiency and later viewing limits remain separate.
A cancelled host attempt has no Compiler result or operator record. A retry is a
fresh declared run linked to its actual cancelled origin.

Context, result, selection and root Source changes withdraw the applicable
recording or selected view. Current generation and selected reference checks
run again after notifications; reentrant changes cannot publish an older view.
Disposal withdraws the ViewModel view but does not physically erase caller-owned
immutable frames or prove current runtime permission.

## Original offline Angular recipe

The separate --operator-recordings Preview profile executes five actual new-host
attempts for each of eleven synthetic examples: original Manifest, diagnostic
operators, one-byte capture, pre-cancelled attempt and a retry. The four earlier
sources remain unchanged. AND short circuit, nested OR/NOT with duplicate
premises, OR/Unknown and successful NOT examples use distinct additional Source
revisions. Original Compiler results and operations remain unchanged.

Each member carries the original Source/input/request/policy/base execution/
materialization/Manifest/response/receipt/result/observation text and digest.
Each actual root diagnostic has independent Manifest, available and one-byte
viewing snapshots, plus the original supplied node/evaluation frames for that
snapshot. No global body map is exposed by metadata admission. Producer platform,
runtime and assembly hashes describe this local export; they establish no
trusted producer registration or authenticity of an arbitrary offline file.

The Angular reader validates all five members and all snapshot modes before
admitting one selected run. It verifies original UTF-8, domain-separated hashes,
lengths, exact protocol fields, original nested observation substrings,
request/Manifest/response/receipt/result bindings, actual diagnostic IDs and
original diagnostic hashes. Same-session origins, known lineage, distinct
run/attempt roles and all-case identity uniqueness are required. Metadata number
tokens must be safe integer tokens; fractional/exponent aliases and duplicate
JSON members, including escaped duplicate names, are refused.

The local version1 recipe is deliberately limited to completed initial-root
Boolean constraints, Requirement conditions and explicit metadata/body gaps.
Constraint records bind the constraints rule and constraint declaration predicate;
Requirement records bind the requirements rule and Requirement declaration condition.
Original operator frames are checked against that exact admitted Source member: bounded AST, typed location,
predicate digest, preorder/path, actual ordered children, AND/OR short circuit,
NOT arity, three-valued truth and original ordered literal digests. Duplicate
premises retain their original distinct ordinals. Unvisited operands are not
invented. Derived evaluation frame bytes are counted separately from retained
operator bytes. No regional Compiler observations are inferred.

A private WeakMap binds the admitted root Source, current projection/member and
immutable verification copy. The full projection fingerprint remains private.
Mutation, replacement or an older asynchronous read cannot attach frames to a
new case/result/Source/run/diagnostic. The store scans global role identities
before, after and during retained admission. Selecting another diagnostic clears
the previous selected frames; replacing Source clears the run as well.

## Explicit Inspector reads

Open the recorded operator example, load a result and explicitly read its fixed
root Source. Choose an existing run under Source, then select an actual diagnostic
in Problems. The Inspector offers Manifest first, the selected original operators
and a one-byte viewing limit. It shows actual visit order, original child
ordinals, skipped-operand counts, literal ordinal/digest and separately expandable
original node and ordered evaluation text. English/Japanese labels and keyboard
focus follow the existing Workbench pattern.

A successful captured evaluation without a published diagnostic has no selected
diagnostic body view. Manifest retains actual execution counters with no stored
operator graphs: a node can be visited even when its body is not retained. A
capture-limited run stays capture-limited under every later viewer choice. A
viewer byte limit does not rewrite a successful original capture or the case
result. Cancelled attempts do not substitute the currently displayed case result
as their own result.

## Requirement conditions and missing evidence

The three additional examples use distinct committed Source revisions9008..9010.
They execute a nested False condition, a True OR short circuit and an Unknown OR
condition through the unchanged Core Requirements rule. Each new host invocation
observes respectively6,2 and3 nodes. A published condition-false diagnostic selects
its six actual nodes and ordered evaluation frame. Missing-evidence diagnostics
at the same typed location do not select that graph. True and Unknown conditions
retain their actual execution counts without inventing diagnostic links.

All three results keep evidenceComplete=false. Neither observing a condition nor
reading its graph supplies evidence, proves Requirement satisfaction or changes
the Compiler verdict. The original Manifest, capture byte limit, viewing byte
limit, cancelled attempt and genuinely linked retry remain independent.
No Domain, Compiler, host or Windows ViewModel runtime contract changes are needed.
The native and Angular Product tests replay all eleven original fixture cases;
negative tests refuse foreign rule/declaration bindings, fabricated missing-evidence
links and false no-evaluation markers even after repairing frame hashes.
