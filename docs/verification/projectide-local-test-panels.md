# Local Project Test results in the paired synthetic clients

Existing authority: #1031, #905, #1030 and #888 PTEST/CI-PROJ/SEM/PROV decisions. This follows the typed Core/CLI and assertion Source navigation. It is an offline consumer implementation, not durable Jobs, current server authorization, shared Merge policy or actual Avalonia acceptance.

## Execution and presentation

Windows pure ViewModel runs ProjectTestPlan over its accepted immutable compilation. The supported evaluator comes from SyntheticProjectTestConfiguration, a fixed offline fixture definition independent of request pins. The preview exporter links that same definition and uses Core to create the Web results. This descriptor is not a binary attestation, producer trust registration or release identity. The portable CLI retains its separate actual Domain binary binding.

Web adds a Tests panel with an explicit Load local Test results action. It never evaluates assertions in JavaScript. Both consumers retain execution, coverage, verdict, freshness, evidence kind and actual discovery/execution counts. Compiler PASS and Test FAIL are separate; viewing or running Tests does not change the Compiler result. Zero discovery, unknown values, unsupported versions, cancellation, stale input, evaluator mismatch, wrong types and resource bounds cannot become Test PASS. The UI describes local scope, shows English/Japanese explanations and can open exact assertion locations in Source. Test lists page at 32 rows while retaining full result counts.

The .NET exporter adds 12 actual Core cases, including Unicode assertion keys, a bounded resource refusal and 33 Tests for paging. The previous 19 fixture cases keep identical object content. Cancelled and stale runs are produced by actual Core controls, not handwritten result objects. There is no manufactured timeout: the current runner has no elapsed-time timeout adapter.

## Local projection admission

The coglatas.local-test-projection/1 envelope is an internal offline preview projection, not a formally adopted Artifact Registry or external acquisition format. It carries original canonical input/plan/result bytes and original Test declaration/assertion bytes. WebCrypto verifies the existing domain-separated SHA256 values for Source, input, plan, result, declarations and executed assertions. Parsed original bytes must match the admitted Source/manifest/semantic-reference projection. Keys, contexts, typed identities, counts, enum spelling and failure-preserving result structure are checked; unknown versions/values, duplicate JSON members, invalid Unicode, oversized/deep data and inconsistent PASS claims are unavailable. Digests establish byte integrity and binding, not execution attestation or permission.

This rendering profile bounds each admitted projection and captured materialization basis to 4 MiB, JSON depth 64 / 100,000 visited nodes, 256 Tests, 1024 assertions, 64 assertions per Test and 4096 bound references. These are display/admission processing limits, not a change to Core capacity or policy minima. Core owns assertion semantics and verdict aggregation; Web does not recompute semantic assertions or turn content hashes into authority.

An admitted report owns a frozen copy. Desired input/generation, context, Source/manifest/map/declaration materialization, result reload, permission loss, reset/disposal and stale async completion invalidate it. Nested mutations are compared with the captured basis at each use. Source actions recheck current read admission and exact member identity; old row objects cannot navigate after a report reload. Windows notification reentry similarly cannot publish interrupted work or retain an old assertion.
