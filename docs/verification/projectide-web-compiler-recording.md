# Local Compiler recordings in the Web preview

Scope: ProjectIDE only, partial delivery for #1034. This offline preview reads original observations; it does not run a Compiler in the browser or claim current actor authorization, producer trust, eligibility, Registry adoption or retention policy adoption.

The dedicated compiler-recordings-v1.json profile retains all twelve compiler-outputs-v1.json cases and their original Source, materializations, publication and Compiler result. Each case adds four actual LocalCompilerRecordedInvocation observations from one owned local session: original Manifest, a separate AvailableOutputs diagnostic rerun, an AvailableOutputs rerun with a one-byte body budget, and a pre-cancelled invocation with no Compiler result. Actual caller run, host attempt and session IDs are preserved. Diagnostic origins point to the original observation and its manifest/receipt digests. A rerun never reconstructs earlier intermediate states.

The reader checks original UTF-8 text digests, fixed formats, capture choices declared before execution, complete fixture materialization bindings, result/execution digests, origins, lineage, distinct identities and atomic body-budget gaps. Available bodies use the shared original-output validator against the admitted publication. A cancelled invocation has no output snapshot, host execution or Compiler result; the case's existing result remains visibly separate. Fixture verification is not an attestation that a trusted producer performed the observation.

The store binds the selected view to the exact case object, bundle membership, admitted Source and package bytes. Source reload, result replacement, selection, clear, access invalidation and a newer query withdraw old pending/published records. Reading the separate output projection does not erase the recording view. These are preview invalidation boundaries, not RLS enforcement.

English and Japanese actions say “View recorded diagnostic rerun.” No action starts a new execution or writes to a backend. Original and budget views display no body rows; diagnostic views display the three produced bodies; cancelled views explicitly say no Compiler result was produced. The package already transports publication and diagnostic body bytes. Changing the view does not minimize transport or physically erase those bytes.

Its producer metadata remains the original observation metadata. The legacy coreProduct field is historical lineage, not a binary attestation.

No ID restamping is allowed. All thirteen previous deterministic export profiles remain byte-for-byte unchanged.
