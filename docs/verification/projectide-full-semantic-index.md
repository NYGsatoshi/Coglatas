# Full semantic index and paired local readers

Existing Language Service work #1030 adds a separate `coglatas.semantic-index/1` over the actual admitted Compiler binding closure. It retains full committed, candidate and hypothetical context identity, the original root input stamp, original regional references, typed entity/port symbols and explicit document definitions. The older `coglatas.semantic-inspection/1`, Compiler results and logical operation receipts keep their original meaning and bytes.

## Scope and bounds

Index construction has a separate derived-work allowance, bounded by the original input execution profile. A caller may narrow that allowance. Every declaration is charged and cancellation-checked before grouping, including an already materialized large binding closure. Exhaustion produces an explicit empty ResourceLimit index; cancellation throws before publication. Reachable-only, missing, denied, ambiguous and unsupported regions never become a complete global index. Index coverage and query scan exhaustion are separate facts.

Typed entity-reference completion requires an actual decoded port declaration and expected entity kind. Definition lookup uses the exact original reference origin. Find References scans original resolved references. Queries return at most 32 results after at most 256 scanned entries, including empty continuation pages. In-process continuation belongs to one immutable index, query kind and exact anchor. Stale input and refused queries expose no borrowed targets or scan facts.

## Paired local consumers

The pure Windows Workbench requires existing original scoped Source admission, current compilation/request/result and current object membership. Selection, Source, input, result, reset, disposal and cancellation invalidate owned state while preserving newer publications.

The offline Angular preview admits original Source bytes, input/result, regional maps and binding frames before reading the separately labelled local index projection. It verifies the canonical index hash, exact roster and prepared query membership/bounds. Ordered reference and candidate membership positions are built once; prepared pages are checked against those positions with the original 32-result/256-scan boundaries, including empty pages. This avoids replaying a full reference scan for every symbol while retaining the separate one-million-work reader cap. A pending read that loses its admitted Source terminates as unavailable without clearing a newer read. The browser computes no Compiler verdict or semantic resolution. Project symbols, typed candidates, reference pages and definitions navigate only to their original admitted regional Source. Current query/page/member ownership, permission checks, generation guards and bounded display pages apply to every action. Full captured index coverage grants no current runtime query/open/apply authority.

The optional `ProjectIde.Preview --semantic-index` exporter writes actual Core-prepared committed, hypothetical, Draft and incomplete examples. The positive profile explicitly declares a larger bounded execution allowance for its 35 additional reference assertions and includes Unicode/control display data; it does not widen any production limit. Original generated captures retain their own input IDs and digests. The optional prepared projection has an explicit 4 MiB export bound, independent of Source admission limits. A caller may narrow it; an unrepresentable projection is absent while the original Compiler result, input and binding remain available. No truncated table is published.

Native replay compares every prepared table with the original Core result; Angular and browser checks open the owning relation Source and its exact definition.

The separate optional `--semantic-index-large` capture retains one actual Core-compiled base with 1,000 added reference assertions and a larger, explicitly test-only bounded execution allowance. Native replay and Angular admission compare the original Source/binding/index and every prepared query page. This is a scaling regression, not #1128 performance or actual editor/Native acceptance.

The separate `--semantic-index-large` capture retains two actual local-region cases under the existing Core cap. The wider case has 1,000 ordinary Project declarations and 500 non-executing RelatedTo relations; its complete Core index is independent of the earlier scoped Source transport refusal and remains unavailable to Web queries. Existing Project Test limits and exact fail/pass/pass verdict checks remain. Native replay and Web tests keep these boundaries distinct and reject removed empty pages and borrowed scan members.
