# Local Test discovery in paired synthetic clients

Existing authority: #1031, #888 A-R2 / IDE-START-01 and the PTEST/CI-PROJ decisions. This extends the Core/portable CLI discovery query integrated in #2084. It does not complete #1031 or independent/runtime P0 #1945.

## Behavior

The Windows pure ViewModel exposes DiscoverSyntheticTests and SelectDiscoveredTest over its accepted immutable compilation. The fixed offline evaluator comes from SyntheticProjectTestConfiguration, independently of request pins. Discovery preserves a separately completed TestRun and the Compiler result. Running Tests again clears the inventory. Exact original row identity, current input/Source/context and notification generations guard Source navigation. Initial cancellation preserves an earlier inventory; cancellation during initial or publication notification cannot publish an interrupted query or remove a newer nested query. This is a pure ViewModel command, not actual Avalonia acceptance.

The Angular Tests panel has a separate List local Test definitions action. It reads an actual Core-produced local inventory without loading a Test run or evaluating an assertion in JavaScript. A separately loaded Test result is retained. Rows show original display name, decode status and known assertion count; unsupported/invalid definitions retain Unknown counts. A count of zero is never substituted for an unknown count. Source actions accept only exact rows from the currently owned frozen inventory. Lists page at32 while retaining the full published count.

The inventory has no execution verdict. Readiness, Source binding completeness and evaluator match are separate facts. A ready definition inventory can coexist with a later failing Test run. Zero, stale input, incomplete discovery and resource refusal remain distinct; refused inventories publish no rows or input/plan stamps. These states are not Test PASS, current authority, producer trust or eligible evidence.

## Local projection and bounds

The separately labelled coglatas.local-test-discovery-projection/1 is an internal offline preview profile, not formal Artifact/Registry adoption. It carries exact input/plan bytes and digests, requested input digest, original Test declaration bytes and actual Core Discover metadata. Source/input/plan/declaration hashes, original membership, stable order, typed context/document/entity locations, decode status, name, counts and evaluator identity are checked. Readiness requires the original current Semantic Inspection; an unexecuted, incomplete binding may admit only its empty refusal with no successful-prefix or binding claim. Hashes bind bytes, not execution attestation or permission.

The existing reader limits remain:4MiB per projection/materialization basis, JSON depth64/100000 nodes,256 Tests,1024 assertions and64 assertions per decoded Test. Unknown formats/fields/statuses, duplicate original JSON members, substituted names/locations/counts, self-rehashed inconsistent plan data and truncated inventories are unavailable. Existing32-case bundle admission is unchanged. The main bundle retains all32 original cases; the separate test-discovery-v1.json profile contains an actual Core binding-budget refusal, produced with --test-discovery. No input/output policy threshold is raised.

The18 existing Test-bearing profiles gain only the new inventory member. All previous case values and canonical plan/run strings are retained. Existing Compiler/regional recording attempts, manifests, receipts and original recording-producer binary identities are preserved, rather than replaced by a fresh execution while adding metadata. The new inventories are generated by Core against the exact same original input/plan/declaration basis. This preservation does not attest new inventory execution or promote a retained recording into current authority.

## Ownership and remaining acceptance

Owned frozen snapshots are invalidated by input/result/bundle/context/permission/reset/reload/disposal changes, nested materialization changes and late asynchronous admission. Copying a row or reusing an old row instance cannot navigate after reload. Loading a Test report invalidates the previous inventory; merely reading definitions does not replace that report. English/Japanese product strings and the existing keyboard/Source focus flow are used.

Developer verification covers Core-produced data, reader/store mutation and generation controls, Windows cancellation/notification reentry, and component actions/paging/localization/Source cleanup. Exact current-source native/frontend/browser/hosted evidence and source review belong on the associated PR; unexecuted checks are not PASS. The standalone unavailable sample must remain within the original bundle bound.

Broader interactive Test editing, richer fixture/expression/assertion families, durable Jobs, remote adapters, required-suite policy, current persisted actor/Tenant/Project/Branch authority, protected export/retention and policy-bound server Merge remain open.
