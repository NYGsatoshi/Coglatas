# Local Test discovery in paired synthetic clients

Existing authority: #1031, #888 A-R2 / IDE-START-01 and the PTEST/CI-PROJ decisions. This extends the Core/portable CLI discovery query integrated in #2084. It does not complete #1031 or independent/runtime P0 #1945.

## Behavior

The Windows pure ViewModel exposes DiscoverSyntheticTests and SelectDiscoveredTest over its accepted immutable compilation. The fixed offline evaluator comes from SyntheticProjectTestConfiguration, independently of request pins. Discovery has a separate notification generation and does not interrupt a Test run already in progress. An explicit run and compilation cleanup invalidate older discovery. Discovery preserves a separately completed TestRun, the Compiler result, and unrelated diagnostic/recording Source selections. Reload and cancellation withdraw only the Source selection owned by the cleared inventory. Running Tests again clears the inventory. Exact original row identity, current input/Source/context and notification generations guard Source navigation. Initial cancellation preserves an earlier inventory; cancellation during initial or publication notification cannot publish an interrupted query or remove a newer nested query. Publication checks cancellation before assignment and withdraws its own canceled inventory even if a notification subscriber throws. This is a pure ViewModel command, not actual Avalonia acceptance.

The Angular Tests panel has a separate List local Test definitions action. It reads an actual Core-produced local inventory without loading a Test run or evaluating an assertion in JavaScript. A separately loaded Test result is retained. Rows show stable Test identity alongside the original display name, decode status and known assertion count; unsupported/invalid definitions retain Unknown counts. A count of zero is never substituted for an unknown count. Source actions accept only exact rows from the currently owned frozen inventory. Lists page at32 while retaining the full published count.

The inventory has no execution verdict. Counts and binding/evaluator flags are displayed only for Ready inventories; stale, unavailable and resource-refused queries show their state without presenting an empty successful count or a confirmed evaluator mismatch. A Ready zero-definition inventory still shows its actual zero and flags. Readiness, Source binding completeness and evaluator match are separate facts. A ready definition inventory can coexist with a later failing Test run. Zero, stale input, incomplete discovery and resource refusal remain distinct; refused inventories publish no rows or input/plan stamps. These states are not Test PASS, current authority, producer trust or eligible evidence.

## Local projection and bounds

The separately labelled coglatas.local-test-discovery-projection/1 is an internal offline preview profile, not formal Artifact/Registry adoption. It carries exact input/plan bytes and digests, requested input digest, original Test declaration bytes and actual Core Discover metadata. Source/input/plan/declaration hashes, original membership, stable order, typed context/document/entity locations, decode status, name, counts and evaluator identity are checked. The original Semantic Inspection supplies binding when present. If execution never publishes that inspection, a separate input/Source-bound binding projection comes directly from the accepted Core compilation; its completeness, retained Test identities/decode states and reference rows must agree with the original discovery plan and verified materialization contexts. When inspection exists, its root Test symbols provide the model-retained decode evidence. If explicit binding is also present, both retained identity/status maps must agree regardless of ordering. A separately decoded Source annotation cannot forge retention after binding exhaustion or relabel an unchanged model-decoded definition. These are bounded consistency checks over local Core output, not authenticated producer attestation. The bundled Angular examples also pin the actual Core-retained Test identity/status roster for each fixed input digest in compiled application data, independently of the mutable served projection. Coordinated plan, annotation and supplementary-binding substitutions cannot redefine that roster. An unrecognized input is unavailable in this fixed synthetic reader; regeneration explicitly consumes all 23 original Core exports through `node frontend/scripts/generate-projectide-test-discovery-evidence.mjs --producer-dir <original-exports>`. The generator is never run during tests or build and must not consume edited served projections. These developer integrity pins do not register a producer, grant Trust/Eligibility or attest execution. They do not constrain the native Core/CLI discovery API. Independent discovery therefore remains available after execution-plan budget exhaustion. Admission uses one detached snapshot throughout all asynchronous hashes and rechecks the live case before publication. Source context/Tenant/Project and the inspection’s own input/Source/context stamps must agree. The bounded basis retains full original Source and input data, declaration records and binding references; unrelated compiled inspection symbols and annotated relation records are omitted, while the full original Source still retains every relation. This keeps the actual 1,001-reference discovery inside the existing 4MiB basis limit. Retained declaration byte hashes, decoded schema versions, and actual Test/assertion limits are checked even for stale or refused queries. Hashes bind bytes, not execution attestation or permission.

The existing reader limits remain:4MiB per projection/materialization basis, JSON depth64/100000 nodes,256 Tests,1024 assertions and64 assertions per decoded Test. Unknown formats/fields/statuses, duplicate original JSON members, substituted names/locations/counts, self-rehashed inconsistent plan data and truncated inventories are unavailable. Existing32-case bundle admission is unchanged. The main bundle retains all32 original cases; the separate test-discovery-v1.json profile contains an actual Core binding-budget refusal, produced with --test-discovery. That dedicated discovery-only sample omits the legacy report it cannot load. Discovery export follows actual Test-bearing Source independently of legacy report naming, including the two-definition main assertion-navigation case. No input/output policy threshold is raised.

Twenty-one existing Test-bearing profiles gain only the new inventory member, including root-diagnostic, predicate, operator and pass recording profiles. The independently pinned simulation-debug-v1.json profile and its --simulation-debug producer retain their exact original bytes and do not include discovery metadata. Reading definitions in that legacy profile remains unavailable; use the main or dedicated discovery example for this feature. All previous case values and canonical plan/run strings are retained. Existing Compiler/regional recording attempts, manifests, receipts and original recording-producer binary identities are preserved, rather than replaced by a fresh execution while adding metadata. The new inventories are generated by Core against the exact same original input/plan/declaration basis. This preservation does not attest new inventory execution or promote a retained recording into current authority.

## Ownership and remaining acceptance

Owned frozen snapshots are invalidated by input/result/bundle/context/permission/reset/reload/disposal changes, nested materialization changes and late asynchronous admission. Copying a row or reusing an old row instance cannot navigate after reload. Loading a Test report invalidates the previous inventory; merely reading definitions does not replace that report. Version-2 Source actions first admit the current scoped publication without replacing shared Source/recording admissions or the existing selection, then recheck the exact inventory, row, result, bundle and generation after the asynchronous read. A separate selection intent and the component focus check prevent an abandoned action from publishing Source after another selection or panel action. An abandoned attempt settles its own loading indicator without clearing a newer discovery attempt. Successful resolution alone replaces the primary Source selection. Each discovery target retains its own verified publication proof and leaves independently loaded recording Source unchanged. Published discovery Source targets retain their admitting bundle, inventory/row and are hidden if that basis drifts. Rejected old/copied rows preserve the current selection; a valid action failure appears in the Tests panel for retry. The Tests live region stays mounted through idle, loading, Ready, Unsupported and Unavailable states. English/Japanese product strings and the existing keyboard/Source focus flow are used.

Developer verification covers Core-produced data, reader/store mutation and generation controls, Windows cancellation/notification reentry, and component actions/paging/localization/Source cleanup. Exact current-source native/frontend/browser/hosted evidence and source review belong on the associated PR; unexecuted checks are not PASS. The standalone unavailable sample must remain within the original bundle bound.

Broader interactive Test editing, richer fixture/expression/assertion families, durable Jobs, remote adapters, required-suite policy, current persisted actor/Tenant/Project/Branch authority, protected export/retention and policy-bound server Merge remain open.
