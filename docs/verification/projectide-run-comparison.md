# Immutable recorded-run comparison candidate

Product-only follow-up to #907, based on ProjectIDE Squash c8d59e7dc011a610f2f1e9a4c780ba350fd7908a. Shared Core comparison is paired with an Angular recording reader/panel and a Windows pure ViewModel lifecycle. Comparing retained recordings starts no simulation, schedules no events, pairs no unrelated Task identities and grants no current authority.

## Supported local profile

Callers supply both actual immutable runs and their exact expected recording digests. The local comparison refuses wrong digests, unsupported engines, different root Tenant/Project/Branch scope and reused run identities naming different recordings. Refused results contain no before/after summary or delta.

Each semantic Source Context retains one body across both roots, every compiled region and all declared authorized captures. One Snapshot ID/version also retains one Context/body. Shared typed identities normalize Contexts and Snapshot IDs before indexing; conflicts cannot silently rebind an origin. The provisional comparison bound is 256 declared captures and 257 compiled regions per run, with cancellation checked through the roster scan. This query bound is distinct from the compiler's existing materialized-supply and closure bounds and is not an approved infrastructure capacity. The exact 256/257 declared-pin tests share one actual materialized fixed Source and compile two actual regions. Earlier fixtures incorrectly supplied 256 bodies or omitted the required declared-context materialization; their failures are retained without relaxing compiler admission.

Unchanged Source Context/body may be compared under different fixed input settings: input digest and Source identity are distinct. Both contexts, source/input/run/manifest digests, execution, coverage, freshness, committed counts and clocks remain inspectable.

Complete comparisons require both recordings to be Completed, Complete and Current for their fixed inputs. The signed observed virtual elapsed difference is after(clock-start) minus before(clock-start), preserving exact integers and start-offset independence. SameInput and SameLimits stay separate. Partial, stale and cancelled recordings are Incomplete, retain observed counts and have no complete elapsed delta. This establishes no Test/Project PASS, Resource feasibility, real-world prediction, performance assurance, eligibility or Merge authority.

## Paired client lifecycle

The Windows pure ViewModel compares a caller-retained admitted before run with its current owned after run. Replacing Source, compiler results, scoped sources, runs or debugger sessions withdraws the pair. Cancellation and synchronous notification reentry cannot publish an interrupted pair or erase a newer comparison. Actual tests pause a debugger, create/recompile/run a duration Scenario, convert/recompile/run a new Draft and compare the separate recordings while preserving the original paused trace. The changed Scenario has an observed nine-tick increase; the equivalent converted Draft has zero additional elapsed difference. These are pure ViewModel checks, not actual Avalonia acceptance.

Angular separately admits both original Source/plan/run recordings and validates the original domain-separated Core comparison bytes and every summary field against them. Its frame bound is 65,536 UTF-8 bytes; capture/region bounds match the local Core profile. It generates no schedule. Both original case instances, their bytes and bundle/request generation fence publication. Denial, reload, result/Source/run replacement, changes to either input or replacement/removal of the second case withdraw the pair. The read-only English/Japanese panel preserves before/after stamps, execution/coverage/freshness, input and bounds equality, observed clocks/counts and the complete-recording elapsed difference. Keyboard focus belongs only to the current pair.
