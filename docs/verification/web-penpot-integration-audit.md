## Localization behavior and limits

The existing `I18nService`, Japanese default, English preference and
`coglatas.locale` persistence are reused. Display language updates immediately
and updates `html.lang`. Application-owned labels, accessible names, help,
validation, safe feedback, counts and dates use typed bilingual catalogs.
Common messages and existing Files/vendor localization are reused.

Feature dictionaries register synchronously at their lazy UI injection
boundaries against the same root language service. Core imports their key
types only; the always-present shell catalog remains eager. Registration is
idempotent per immutable catalog reference. This avoids shipping unopened
Project/Messaging/Files dictionaries in the initial bundle. The initial eager
attempt exceeded the existing 1.02 MB error budget by 6.36 kB; it was repaired
without changing budgets, route gates or dependencies. The intermediate lazy
build with the final shell catalog measured 918.33 kB versus the original
906.07 kB; final candidate results are recorded below.

Raw request/command state remains separate from translated display projections.
Typed key metadata marks application-authored fallbacks and feedback; arbitrary
server/user text is not translated by string matching. Files metadata binds to
its original text so replacing a message cannot retain a stale translation key.
User titles, bodies, names, filenames, Stage labels, drafts, identifiers and
wire enums retain their values. Calendar-only dates format in UTC to prevent
display on a neighboring day; timestamps use the selected locale and existing
browser time-zone behavior. Date inputs/API values remain canonical.

The new browser journey changes language through Account preferences, visits
Projects, My Tasks, DM and Files, preserves supplied Unicode content and an
unsent Message draft, checks locale persistence after reload, prevents
unexpected mutation requests, checks overflow and runs axe on Files. Mounted
component tests additionally check hot-switch state/DOM/focus and no extra
HTTP reads. These are frontend fixtures, not backend acceptance.

This is core-workflow localization, not a claim that every repository screen
or backend-authored diagnostic has been translated. Administrator/audit and
Announcements surfaces outside the assigned sprint remain separate work.
New unsupported ProjectIDE, dedicated multi-thread persistence, Project Files
or Artifact Repository APIs are not invented by this change.

## Hosted focus-race follow-up

Hosted frontend checks at `47965d5f` succeeded but exposed one retried Channel
settings focus case. The race was reproduced deterministically: closing and
reopening before Angular rendered the closed `@if` state retained the same
close-button DOM, so the ViewChild setter did not rerun and the queued old
trigger-focus callback could win. The current close control is now focused on
every open, and queued trigger return is skipped if the panel reopened.

The new focused unit and browser regression failed on the original source and
passed after the repair. Agent C verified 36 Angular tests, all eight narrow
browser-file cases and 30 isolated stress repetitions with retries disabled.
The existing native-select Escape/reopen, keyboard, draft-preservation,
containment and no-mutation assertions remain. No sleep, timeout or retry policy
was relaxed. Final hosted checks must qualify the candidate containing this fix.
