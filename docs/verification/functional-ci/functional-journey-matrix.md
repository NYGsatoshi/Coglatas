# Functional CI journey matrix

Status: canonical P0/P1 user-journey inventory for Issue #577 / FCI-01.

Policy terms in this matrix are defined in
[`functional-test-policy.md`](./functional-test-policy.md). Gate execution and
release ownership are defined in
[`functional-gate-topology.md`](./functional-gate-topology.md).

## Reading the matrix

- **Owner** names the primary domain that is responsible for the journey.
- **Mock policy** is the maximum mock boundary allowed for owner credit.
- **Gates** are target Functional CI ownership, not a claim that every target
  workflow is already wired. FCI-08/09/10 implement the remaining topology.
- **Current mapping** records existing evidence. A mapping marked `focused only`
  does not satisfy the real-functional owner slot.
- **Status** describes whether an executable real owner exists on current
  `main`. It is not a historical CI result for a particular SHA.

Runtime budgets (`B1`-`B4`) are defined in the policy.

The seven-owner Full/Extended artifact contract proves only the implemented
domain slice. It does not complete every historical P0/P1 matrix row or replace
independent MBJ, My Tasks, grant/source, #481, or #482 acceptance. Source status
does not establish hosted execution for the current SHA.

## FCI-04 required execution contract

`FUNC-TASK-001` retains one canonical owner in
`tests/functional/project-task/core-golden-journey.spec.ts`. The focused runner
`tests/ui/run-real-backend-fci04.mjs` selects that owner by exact gate/Journey/
real-backend tags and requires one passing attempt plus every stable gate step.
Fast requires STEP-01/02/05..11; full adds STEP-03/04 for Workspace context,
Project/Task/My Tasks navigation, and Task mutation/fresh read/reload. Result
replay, browser reload, and session re-entry must preserve the persisted content
hash and body; logout denies both owner APIs and the protected browser route.

The protected P0 runner executes fast before its independent legacy manifest.
Main's artifact-reuse acceptance explicitly executes full. Trusted FCI-04
write-access branch pushes and protected `fci04` dispatch run both selections
against the exact candidate in one isolated real stack. Missing/skipped/retried
owners and missing steps fail; green static preflights alone are not real-stack
execution evidence. Broader gate routing/sharding remains owned by FCI-08/09.

## Owner-test rule for duplicate coverage

For each stable ID, only the matrix-designated real owner is allowed to satisfy
that journey in a blocking Functional gate. Broader tests may re-exercise the
same path, but are reported as `focused regression`, `negative expansion`, or
`release projection`.

Examples:

- #481 replays core auth/Workspace/Project/Task/File/execution through a public
  endpoint to prove deployment topology. It is not a second PR owner for those
  feature journeys.
- #482 spans many screens to detect integration regressions. It is not allowed
  to make a missing Files, Messaging, Announcement, or Audit owner test appear
  implemented.
- screenshot assertions inside `angular-smoke.spec.ts` may block their own
  visual regression contract, but they do not satisfy a real-functional stable
  ID.

## Change requirement

Any PR that changes a Functional test in a way that affects journey semantics,
owner status, mock boundaries, stable test titles/manifests, gate ownership, or
runtime budget must update this matrix in the same PR. New journeys receive a
new stable ID; existing IDs are never reassigned to a different user goal.
