## Actual producer and paired consumers

The Windows pure ViewModel requires explicit admitted scoped Sources and the actual producing plan before `RunSyntheticSimulation`. Its explicit manifest retains the caller's run identity, virtual start and limits. It calls the shared actual Core engine, retains its immutable completed or partial/cancelled recording and exposes event-to-original-Source navigation. A copied or previous run's event cannot become a current target. Compiler/Test results and immutable plan definitions are not overwritten by simulation. Reload, new input, reset/disposal and synchronous notification reentrancy invalidate pending publication and display without mutating independently retained old evidence.

The new isolated preview `--simulation` profile emits actual Core results for baseline, Scenario and converted Draft in four families: local Task chain, cross-Project dependency, required Unknown (no plan/run) and a real two-event run bound. Every produced run includes its original canonical result text and domain digest. Run identity and manifest are distinct per captured input. Existing exporter profiles and their original bytes must remain unchanged. The deeper plan examples explicitly retain their existing400k compiler profile; run bounds are independently fixed in each manifest, with no global/default/CI policy change.

Angular's permission-gated **Open simulation result example** fetches the real hosted asset. Explicit result, fixed-Source and recorded-simulation admission are separate actions. Opening a recording never starts a new run, invokes a provider or performs JavaScript scheduling. The read-only Source panel shows run identity, actual execution/coverage/reason, virtual clock, completed Task count, original result/digest and event buttons with exact typed Source targets. The definition remains separate from its recording, and execution completion never becomes Project/Test PASS.

The reader bounds original bytes, rejects duplicate/unsupported shapes, verifies original result and manifest domain hashes and independently pins the currently implemented engine/policy. It binds exact admitted plan/input/Source digests and context slots. It indexes plan Task/dependency membership, checks processed and enqueue sequence uniqueness, monotonic exact tick strings, unique start/end transitions, matching elapsed durations, prerequisite-end/lag lower bounds, counters, coverage and the fixed no-outcome-assertions evidence axis. It checks consistency of supplied events; it does not generate/reorder events or rerun the scheduler/Compiler/predicates. A declared engine digest and internally consistent artifact are not producer trust or current access authority.

Returned run data/events are fresh immutable views. The admitted scoped-Source basis includes the original run frame: same-object byte/input/result mutation withdraws run and Source targets. New result, Source read, context/permission/identity boundary or interrupted asynchronous admission cannot publish an older recording. Mutation during admission becomes explicitly unavailable, rather than leaving a loading control. Current permission is checked by visible handlers and after asynchronous completion; actual server/job authorization is a separate unimplemented gate.

## Verification and limits

Component/browser checks exercise the actual example entry, explicit keyboard loading and Source focus, en/ja display, desktop/mobile accessibility and no modifying requests. Only the altered-byte browser negative intercepts the actual simulation asset; positive journeys fetch hosted Core-generated bytes.

Initial developer failures are retained. The first duration negative wrote its existing101tick value; it now changes the actual end by one tick. Component tests initially did not await the native asynchronous hash reader; they now wait for its actual ready state. Neither correction relaxes production validation, assertions, timeouts or runner configuration. Full-scope counts/source/review/CI qualifications are recorded in the continuation handoff.
