# Sonar coverage phase 2: independent Angular producer

Parent: PR #2278 at `d1827afb779091e977b02c94311a65d9d0368a03`. Baseline run [45804716868](https://github.com/NYGsatoshi/Coglatas/actions/runs/45804716868), attempt 1: Windows 406 s, Python/GCP 396 s, combined Node/Angular 670 s, Angular coverage command 404 s. Producer timing only; final scanner and queue time are not included.

This stacked change splits the Angular coverage command and native retention into an independent credential-free job, keeping the existing Node cohorts together. All four producers depend on the same trusted target, and the scanner requires all four to succeed. Existing npm installation validation, native report generation, scanner begin/build/end, report paths, source exclusions and Quality Gate are unchanged. Node and Angular publish separate compact exact-attempt digest-bound handoffs; retain the original native artifacts. Neither is optional.

Expected benefit: overlap the 404 s Angular command with the other producer work. The estimated producer critical path is approximately 7–8 minutes, not an observed candidate result. Measure actual elapsed and runner minutes including duplicated setup; do not infer a passing gate from producer completion. No dependency cache or cross-run report reuse is introduced because the existing npm policy uses isolated caches and verified fresh installs.

Qualification: compare actual native per-file line/branch counts and source identities, check official Cloud ingestion and Quality Gate, and record timings. The existing owner-push Sonar router accepts only main-target PRs; a stacked PR targeting the parent branch is intentionally not token-eligible. Static workflow checks and handoff regression controls can run on the stacked PR; full Sonar qualification requires the parent to land and the child to be retargeted to main, followed by an eligible exact-head owner push. Do not broaden the credential routing policy to test this change. No merge before qualification.
