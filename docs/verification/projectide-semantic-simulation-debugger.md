# Shared semantic simulation debugger

Authority: #907 accepted fixed-input simulation/debugging loop and DBG-02, #905 actual plans and #888 A-R2. This is the actual pure elapsed Task control engine and Windows pure ViewModel adapter. It is not full #907, a Web live executor, server job or actual Avalonia/native acceptance.

## One event engine and immutable control states

`SimulationCursor` is the single implementation of preparation and bounded event transitions. Both `ProjectSimulation.Execute` and `ProjectSimulationDebugger` consume it. Original engine identity, scheduling policy, event ordering, ticks, operation charging and terminal result bytes remain unchanged. Compatibility requires actual reexport and replay checks; a new step API is not permission to reinterpret old artifacts.

The debugger owns one immutable run manifest and a separate versioned controls document that binds its digest, supported semantic points/commands and provisional control/inspection limits. A prepared session is Ready; after an event or breakpoint it is Paused; only an actual terminal `ProjectSimulationRun` makes it Terminated. A paused prefix is neither a cancelled run nor a completed result. Immutable snapshots bind control revision, original manifest/input/plan, last committed virtual clock, next semantic event, trace-prefix digest, breakpoint resolutions and optional inspection/result digests. Independently retained snapshots/events never change when this run advances or another input is compiled.

Every command carries the exact run-manifest digest and control revision. A wrong-run/stale command returns no snapshot and cannot advance work. Per-instance synchronization admits only one concurrent command for one revision; no unrelated run or database transaction is paused. Caller breakpoint enumeration is bounded outside the gate and the stamp is checked again afterward, including synchronous reentry. Accepted command count, breakpoint count/aggregate bytes and task-inspection work/bytes are separately bounded; they do not increase compiler/run/CI budgets. Snapshot reads reuse the immutable current view rather than performing hidden work.

## Supported semantic controls

An event step commits exactly one actual start/end transition. Continue stops before a resolved Task-start or Task-end event, retaining the upcoming event's own tick separately from the last committed clock. Resume passes that same breakpoint event once rather than repeatedly stopping without progress. Breakpoints bind exact plan digest, captured context, document/entity/property identity and point kind. A supplementary buffer span cannot override semantic identity; the resolution publishes the actual canonical bound location. Wrong plans, foreign versions, unsupported points and nonsemantic property positions remain explicitly unresolved, never silently mapped elsewhere.

Task Step Over starts only at the selected current atomic Task-start boundary and records all relevant parallel events until that Task ends. A parallel breakpoint can interrupt it. Dependency edges are not function calls. This lowerer has no executable composite instances, so Step Out is visibly unsupported; composite Into/Over/Out, conditions/hit counts/temporary points and full watch evaluation remain open. There is no fabricated call stack or implicit jump through a causal DAG.

Task inspection exposes actual Ready/WaitingPrerequisites/WaitingLag/Running/Completed state, original typed location, elapsed duration, committed start/end/remaining ticks and original fixed typed input defaults. These are not evaluated outputs or a real-world observation. Multiple unsatisfied prerequisites retain their original relation/end-point origins; bounded subsets have exact total counts and explicit partial coverage. A completed prerequisite can leave a distinct lag wait. If runtime preparation exhausted its budget before indexes/queues were complete, inspection is explicitly unavailable rather than describing a partially indexed Task as Ready. The original failing regression for that authoring defect is retained.

Cancellation, overflow and run event/time/operation/trace bounds retain the same committed terminal prefixes as uninterrupted execution. No control performs a clock read, RNG/provider/network/secret operation, Source mutation, shared reservation, hot reload or predicate reimplementation. A completed simulation still evaluates no Project/Test outcome assertions and grants no current authority.

## Windows pure adapter and reruns

The Windows pure ViewModel requires explicit admitted Sources and an actual producing plan before beginning a debug run. Controls accept only its current immutable snapshot and fence generation, plan/request/session and notification reentry. Old-run/copy events cannot become current targets. Terminal evidence is exposed separately from paused control state and never overwrites Compiler/Test results. Scope reload, new input, reset/disposal withdraw snapshots/control/targets; private session references are detached before disposal. A busy notification cannot recursively apply a second step for one user action.

The actual Core loop test pauses before a semantic Task point, prepares a new typed duration Scenario, recompiles it, converts/recompiles a new Draft and starts distinct runs. Their changed clocks/manifests are compared while the original paused Source/input/trace remain unchanged; the old run can independently finish under its own original manifest. New clients/hosts must enforce current authority before viewing/controlling any retained run; pure object ownership is not authorization.
