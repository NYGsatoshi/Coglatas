# Original Compiler output snapshot consumer

Existing work: #1034 under #905/#888. This is a read-only synthetic Web consumer of the bounded Pure Core output snapshot foundation. It does not complete shared Provenance/Explain, full pass recording, runtime storage or actual Native UI acceptance.

## Producer and identities

The offline Preview exporter adds an explicit --compiler-outputs profile over twelve actual committed, Scenario and prepared Draft inputs. It compiles each original Source with its declared captured dependencies, then calls ProjectCompilerOutputSnapshot.Read on that owned result. Both Manifest and explicit AvailableOutputs frames preserve original canonical metadata text/digest and original produced body text/digest. Pass, Fail and Inconclusive remain the Compiler's independent original verdicts. One actual snapshot has a one-byte output-body budget and an explicit all-or-nothing BodyBudgetExceeded state.

The new profile assigns each distinct external Source its own fixed committed revision and snapshot identity before compilation. An initial candidate reused legacy publication fixture identities for different true/false/unknown Sources; the new whole-bundle identity regression failed on both hosts. The correction regenerates actual Sources, pins, Compiler results and captures through the existing helper's explicit new-profile identity option. It does not restamp already-produced output bytes. Other exporter profiles retain their original default behavior and bytes.

## Reader and view

The typed reader requires the currently admitted scoped Source/publication, checks the original selected snapshot metadata digest and exact fields, and reconstructs only the expected capture metadata from that already verified publication. It binds the full original Compiler result digest, input, Source, context, Compiler, independent result axes, stages/output references and current fixed-input freshness. Each retained body must exactly equal the original admitted publication body with its original digest. The reader derives byte totals and atomic capture/gap state from original UTF-8 body bytes and the bounded requested budget. Correct rehashing cannot turn a foreign result, altered body, false capture success, fabricated earlier recording or Trust/Eligibility claim into admission. Duplicate metadata members and unrecognized fields are refused. No Compiler execution is implemented in JavaScript.

The default view is Manifest; available produced bodies require a separate explicit read action. The synthetic bundle and scoped publication admission already transport those bodies. Manifest display is not a claim that the client has never downloaded or retained them. This view performs no additional acquisition, persistent storage, Pin, deletion, privileged export or modifying request.

The owned store binds the selected case object and bundle membership, exact scoped admission and query generation. Input selection, result reload, Source readmission, access clearing and reload withdraw both pending and published views. A newer query owns publication; an old asynchronous response cannot reappear under a reused case key or another immutable input. Original caller-owned frozen snapshots are not physically erased by withdrawing the view. Localized read controls move keyboard focus only to the still-current output panel, and original body text is rendered through text interpolation in a bounded scrolling preformatted view.
