# Sonar coverage phase 4a: native .NET sharding qualification

Parent #2280 at `7490f0477c8a17d7dee2e5823a2dd889bd31bc2b`. The observed #2278 unfiltered native Ubuntu collection was 1,142 seconds. This is a credential-free qualification PR, not a change to production Sonar publishing.

The dedicated workflow runs an unchanged full baseline and four disjoint VSTest class/namespace cohorts on isolated Ubuntu/PostgreSQL runners at the exact PR head. The initial cohorts are files/projects/tasks PostgreSql, remaining PostgreSql, SecurityArchitecture/Aq outside PostgreSql, and the logical complement. These are a starting partition, not an asserted runtime balance. Each executes original Coverlet OpenCover and TRX with the existing producer build, privacy, migrations, physical test-only rebuild, source mapping and native provenance verification. All five retain original artifacts. The comparison job requires current-attempt artifacts only, validates the exact source/tree/run/attempt, checks retained binary bytes against receipts and requires the baseline/shard build identities and source mapping to match.

The verifier compares actual passed TRX class/method/display-name multisets (including theory-row multiplicity) with no cross-lane overlap, and the union of native tracked src/tools C# sequence and branch point identities plus hit states against the unfiltered baseline. It does not merge/rewrite reports or claim a passing Sonar quality gate. Generated sources remain in retained originals. Missing/extra points, changed hit states, tests, binaries, or evidence fail closed; strict equality may reveal order-sensitive coverage and requires investigation rather than bypass.

Measure each lane's native test duration, end-to-end job duration and compute overhead. Do not promote sharding to the authenticated Sonar workflow until real test identity and coverage equivalence, runtime benefit and actual scanner ingestion are demonstrated. This pilot intentionally runs the full baseline too, so it is not an immediate CI speedup. The existing production Sonar workflow, router, exclusions, thresholds, test selection and report paths are untouched.
