# Paired recorded predicate Inspector

This bounded Product slice advances #1034 through the Angular offline Workbench and Windows pure ViewModel. It does not activate an Avalonia application, a browser Compiler, remote data acquisition or current runtime disclosure authority.

## Intended invocation and lifecycle

The Windows caller declares the exact intended pre-run local manifest with its actual predicate request before the Waiting notification. Admission requires that same manifest object, the exact request token and the opaque owned response/receipt pair. A whole genuine older invocation is refused even when its request, generation, result and pure predicate record digests are identical. The old host admission cannot accept a predicate invocation or implicitly supply predicate bodies. Reset, disposal, a newer request and reentrant notifications withdraw stale acceptance. Explicit predicate completion permits a resource result without a model; cancellation has no invented Compiler result.

Source admission and recorded metadata are explicit separate reads. Changing Source withdraws displayed metadata and selected bodies. Diagnostic selection withdraws selected bodies. Every selected read still requires the exact accepted compilation, root Source, selected diagnostic and owned predicate record; default Manifest exposes no body map. Original capture gaps remain distinct from atomic viewer-budget gaps.

The Angular reader consumes a separate bounded offline projection. It hashes the original UTF-8 source/input/request/policy/base-execution/materializations/manifest/response/receipt/result/predicate/diagnostic/snapshot/body text before admission. It validates every recorded member and available read mode, including currently unselected bodies. Duplicate JSON fields, unsafe protocol counters, false semantic metadata with rebound hashes, foreign members, reused run identities, false origins and cancelled-result substitution are refused. Original body text is never reconstructed or reserialized into a hash subject.

Private admission records bind the exact selected fixture member, projection and explicit root Source. The complete root fixture fingerprint stays in a private WeakMap because it can contain every recorded body; it is not published as Source metadata. Published metadata contains no complete body map. An asynchronous read must still match its original member bytes, Source, selected diagnostic and lifecycle when it completes. Choosing another input, reloading Source, replacing a member, losing permission or clearing protected state removes stale views. These local UI guards do not establish server authorization.

## Actual fixed examples

The new --predicate-recordings exporter reuses four unchanged root fixtures. Each case has five actual local invocations: original Manifest, diagnostic capture whose origin is the original run, one-byte capture whose origin is the diagnostic run, cancellation, and a retry whose origin is the cancelled attempt. Run and attempt IDs are fresh actual random identities. The exported snapshots come from each response's own compilation. Cancellation retains no result, predicate record, diagnostic snapshot or bodies.

The fixture preserves raw original frames and declares its observed runtime/platform and assembly hashes as observation metadata only. Cross-platform comparison applies to deterministic frame subjects. Complete random-identity documents are retained separately and must not be normalized into byte parity. CompilerHostRequest.ExecutionInputData retains the already existing two-digest hash subject and is JsonIgnore; four original serialized request golden hashes verify that version-one request bytes remain unchanged.

The Source panel verifies a selected run before the Inspector can read a selected diagnostic's original arrays. Manifest is the default. Explicit available-array and one-byte viewing choices retain original capture state separately. A successful rule array without a diagnostic is not exposed, absent arrays are not recovered, and viewing a cancelled attempt leaves the case result unchanged. English/Japanese labels, keyboard operation and focus are covered separately.
