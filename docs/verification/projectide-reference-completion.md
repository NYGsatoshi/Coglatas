# ProjectIDE typed reference suggestion preview

This is a partial implementation of #1030 under the existing #888 shared Core
and parallel Web/Windows preparation scope. It suggests local declarations for
an exact entity-reference port in an already admitted immutable input.

`CompilerSemanticInspection.CompleteEntityReference` derives the expected
declaration kind from the canonical port type. It excludes opaque, invalid,
ambiguous and other-kind symbols. A request carries the exact input digest;
foreign context, stale input, unavailable origin, unsupported type and foreign
continuations have explicit states. Each page scans at most 256 local symbols
and returns at most 32 candidates. The opaque in-process continuation belongs
to one inspection and origin. Cancellation is checked before and during scans.
Coverage and remaining pages are separate; an empty partial page proves no
global absence. The existing canonical JSON processing bound is preserved.

The offline preview exporter runs this Core query and includes its bounded
projection alongside the optional semantic inspection. Angular reads and
validates the projection against the exact input, canonical port, declaration
identity and display name. It does not recompute type compatibility. Without
an inspection the projection stays inert for legacy fixture compatibility.
The Inspector opens a candidate's declaration through the existing Source-map
resolver. Read permission is checked again on activation; context, result,
selection, map replacement and permission loss invalidate retained navigation.
The Windows pure ViewModel queries the same Core method and rechecks canonical
page/candidate membership and Source mapping when opening a suggestion.

The `pass` synthetic fixture now contains one defaultless entity-reference
input port. Its Source, input/result digests, semantic inspection and map are
regenerated by the actual .NET exporter. Fixture contract tests reproduce the
Core query and compare states, coverage, truncation, input digest, identities
and names. Product unit tests cover paging, scan bounds, cancellation, context
dimensions, ambiguity and ViewModel lifecycle. Angular tests cover the reader,
store, localized controls and permission loss.

This preview performs no reference insertion, Draft edit or Rename. It does
not establish runtime authorization, incremental indexing, external snapshot
completion, connection applicability, real data, actual Avalonia UI acceptance,
formal Artifact/Trust adoption, Native activation or Release readiness. #1030
remains open. Security-branch dependencies remain assigned to P0 #1927;
this change does not modify that branch or its checks.
